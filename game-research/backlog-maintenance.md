# 研究清单组织与维护

清单用于选择下一题、恢复工作和复用成果。已有宿主清单时接到原入口；没有时，可在用户指定的包外目录裁剪[空白模板](../templates/research-backlog.md)。本包不携带维护者的实际研究队列，也不因登记事项启动任务、调度或其他会话。

## 每题一份当前记录

按当前执行、待研究、暂停或受阻、已有成果组织，空组省略。每题使用稳定 ID，保留目标、范围、预期成果、选择依据、关键证据、投入条件、实际阶段与下一动作。信息较多可用同页卡片；不要为了压成一行删掉决定先做谁所需的信息。直接阅读该题应能判断研究什么、为何值得做、何时能进入及结果如何复用。

简短总览只用于比较和定位，详细来源、成本、失败、阶段历史和回执留在原研究目录；不得另维护一套可写状态。未开题的长线索保存在原选择说明中，不为每题创建空目录。已有成果仍有接入或返修时，续写原题；新稿待审不降低旧正式版的接受状态。

## 登记、去重与排序

先按路线、对象、版本、范围和问题核对已有清单及报告。命中同题就更新原 ID；整作与局部、原版与重制不自动合并。只有实质新问题、来源增量或改变判断的反例才新增。价值、证据准备度、相对投入、用途和容量决定顺序；编号、发现日期和完成时间不自动成为优先级。暂停与后续授权沿原决定。

用普通 Markdown 标题与链接导航，稳定 ID 可作为标题，问题另行显示。重排后检查上下文指代、先后依赖、旧路径和入站锚点。原方法和领域事实仍各有维护源，不为清单维护新增服务或重复正文。

## 交付、修订与异步回执

交付或修订前回读原条目，对照本批范围、精确成果版本、审阅结果与尚未回答的问题。研究、本地接受、线上同步分别写实际状态：未接入、已排队、部分、退回、未知和不适用均保持区别；文件存在或聊天说已完成不能替代对应回执。没有外部消费方时写不适用，不创建虚构接入待办。

报告 owner 接到接受、退回或上线回执后，核对其版本与实际覆盖并更新原题。等待期间每次恢复本批先读原停点；保留接收方、原记录、恢复条件与下一责任。协调方处理容量与漏回，不另建定时器。原始回执和历史失败保持原样。

结题后仍保留目标、实际成果范围及其可支持的判断。放弃项说明原因和恢复条件后沿原记录归档；受阻项保留可发现入口。收尾核对稳定 ID 唯一、链接可达、原条目与权威成果/回执一致。普通清单文字调整不重开研究或报告审计，报告实质修改沿原交付合同。
