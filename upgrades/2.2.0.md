# 2.2.0 upgrade and recovery

The previous independent version is 2.1.0. This additive release keeps existing research, rendering, source-selection and optional peer contracts. New reader and editor branches are opt-in. Keep reports, assets, run receipts, credentials and host configuration outside the module. Installing Research does not install a model service or select client Skills.

For an independent Git checkout, first inspect status and save a recovery branch at the current commit. Preserve edits with their owner; use a separate checkout for conflicts. Fetch the reviewed published tag, inspect the diff, and switch only from a clean checkout. Run the module verifier and the affected reader tests before use. Restore the saved recovery ref from a clean checkout to return to the previous payload; preserve new reports and local environment separately. Do not reset or clean another owner's work.

For an AWS-managed installation, use that installer’s preview, edited-file conflict checks and returned transaction ID. Roll back through the same installer. Research's peer manager fetches optional modules; it is not a self-upgrader. The standalone release checks exercise local baseline-to-candidate application, edited-file conflict and exact rollback; AWS aggregate installation is validated separately by its release owner.

For client-installed Skills, upgrade each platform through its actual Skills manager and review conflicts independently. Research’s bundled .agents methods are package-owned, not an authority to overwrite separate Codex or CodeBuddy installations. The release retains all four bundled methods. There is no new automatic scheduler or routing guarantee.

Optional system HTML branch: Python 3.10+, lxml, PowerShell 7 ConvertFrom-Markdown. Override its existing executable with --powershell when needed. Markdown primary reports and independent prototypes remain useful if conversion is unavailable. The editor uses lxml and AWS_RESEARCH_COPY_POLISH_DIR only when explicitly selected; preserve the executor version and host authorization separately. Existing study files do not gain an automatic renderer or approval.

Previous failure receipts retain their identity. Rebuild changed projections in a separate output/case, verify source hashes, dependencies, navigation, focus, input and prototype state in the actual browser. No package rollback can undo an online call or decide report adoption.
